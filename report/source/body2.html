SOFTWARE DESIGN

3.1 System Architecture Overview

SpecFix follows a layered architecture ({{ref:fig-arch}}). The presentation layer is a Next.js 15 application using React Server Components and server actions, so no public REST API is exposed. The application layer resolves the user and tenant on every request. The domain layer is a set of TypeScript packages that return data only, and the data-access layer is the only code allowed to issue SQL. The infrastructure is Supabase (PostgreSQL with pgvector, Row-Level Security and authentication), Azure OpenAI / OpenAI endpoints and GitHub Actions CI. Two decisions run through the design: work belongs to a ticket version (identified by a content hash), so artefacts become stale instead of silently attaching to changed text; and tenant isolation is enforced in the repositories, by RLS and by a dedicated test suite.

3.3 UML Diagrams

3.3.1 Use Case Diagram

Four actors use the system ({{ref:fig-usecase}}). The Organisation Admin generalises the Product Manager and additionally manages workspaces, ingestion and analysis; the Test Engineer works on scenarios and scaffolds; the Evaluator runs evaluations and reads metrics.

3.3.2 Class Diagram

A Tenant owns Projects and Memberships; a Project owns Tickets; each Ticket has TicketVersions, each version has AnalysisRuns, and each run produces Flags with an append-only list of FlagDecisions ({{ref:fig-class}}). Scenarios are generated from resolved flags and can have one TestScaffold, an Embedding and traceability links.

3.3.3 Sequence Diagram – Ticket Analysis

{{ref:fig-seq}} traces one analysis: the latest version is loaded through a tenant-scoped repository, the ticket is rendered with neutralised delimiters, the Extractor returns candidate flags, the output is validated and spans verified, the Critic returns keep/prune verdicts, safety rules are applied and the run, flags and every model call are stored.

3.3.4 Entity Relationship (ER) Diagram

{{ref:fig-er}} shows the fifteen principal tables and their one-to-many relationships; every tenant-scoped table also carries tenant_id with Row-Level Security. Scenario reviews, traceability links and three embedding tables complete the schema.

3.4 Database Design

PostgreSQL on Supabase is the only database; seven transactional migrations create the schema, and llm_calls logs every model call with its cost.
