ABSTRACT

Software requirements are usually written as short tickets or user stories in tools such as Jira. These tickets are frequently ambiguous or incomplete: a word such as “quickly” hides a decision, an acceptance criterion cannot be tested, or an edge case is never mentioned. Developers fill the gaps with assumptions, and the mismatch with business intent is discovered late — in QA or after release — when it is most expensive to fix.

SpecFix is an AI-assisted requirements-quality platform that catches these gaps before development starts. A ticket goes in; structured flags come out, each with a category (missing information, vague language, contradiction, unhandled edge case, security/compliance gap or untestable criterion), the exact text it refers to, why it matters, and a question for the product manager. An Extractor language-model call proposes candidate flags and an Adversarial Critic call removes false alarms. A human reviewer then accepts, edits or dismisses every flag in a web dashboard, with an append-only audit trail and no automatic resolution path.

Once a ticket is approved, the Spec Compiler turns its acceptance criteria into Gherkin scenarios, and a deterministic generator turns each approved scenario into a Playwright test scaffold with marked placeholder selectors. A traceability graph backed by pgvector embeddings shows clause-level coverage and detects scenarios that drift when a ticket changes.

The system is a TypeScript monorepo (Next.js 15, Supabase PostgreSQL with Row-Level Security and pgvector, Azure OpenAI / OpenAI, zod, Vitest). Every model output is schema-validated, ticket text is always treated as data, every model call is logged with its cost, and the Critic’s precision is only reported next to a random-pruning control. On an 11-ticket gold set the Spec Compiler covered 91.7% of acceptance-criteria clauses, made one unsupported coverage claim in 42 scenarios (2.4%), and produced 42 of 42 valid scaffolds at about US$0.0004 per ticket.
