# API-121 Rate limit the public API

## Description

One integration partner's retry loop took the API down for eight minutes last
Tuesday. We need rate limiting so a single client cannot exhaust capacity.

Limits should be generous enough that normal usage never notices and the API should
stay fast.

## Acceptance Criteria

- Requests over the limit are rejected
- Clients can tell how much quota they have left
- Limits are configurable without a deploy
- Rate limiting does not slow down normal requests
